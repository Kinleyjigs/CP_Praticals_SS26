### a.For the Knuth-Morris-Pratt (KMP) algorithm, compute the Longest Prefix Suffix (LPS) array for the pattern: "ABABCABAB"

The LPS (Longest Prefix Suffix) array stores the length of the longest proper prefix that is also a suffix for the substring ending at each index. This allows the KMP algorithm to skip unnecessary comparisons.

Pattern: A B A B C A B A B
Indices: 0 1 2 3 4 5 6 7 8

| Index | Substring     | LPS Value | Explanation                                   |
|------:|---------------|----------:|-----------------------------------------------|
| 0     | A             | 0         | No proper prefix exists.                      |
| 1     | AB            | 0         | Prefixes: {A}; Suffixes: {B}. No match.      |
| 2     | ABA           | 1         | Prefix A matches Suffix A.                    |
| 3     | ABAB          | 2         | Prefix AB matches Suffix AB.                  |
| 4     | ABABC         | 0         | 'C' breaks the pattern; no prefix matches.   |
| 5     | ABABCA        | 1         | Prefix A matches Suffix A.                    |
| 6     | ABABCAB       | 2         | Prefix AB matches Suffix AB.                  |
| 7     | ABABCABA      | 3         | Prefix ABA matches Suffix ABA.               |
| 8     | ABABCABAB     | 4         | Prefix ABAB matches Suffix ABAB.             |

**Final LPS Array:** [0, 0, 1, 2, 0, 1, 2, 3, 4]

### b.For the Rabin-Karp algorithm:
- **Explain how hash collisions are handled**
- **State its average-case and worst-case time complexities**

A hash collision happens when two different strings produce the same hash value. a false positive match.

The algorithm handles this through a two-step verification:
1. Hash Match: The algorithm slides over the text and calculates the hash of the current window. If the window's hash does not match the pattern's hash, it moves on immediately.

2. Character Check: If the hashes do match, the algorithm does not assume the strings are identical. It performs a manual, character-by-character comparison of the pattern and the current text window.

    - If they match, a hit is recorded.
    - If they don't, it was a collision, and the algorithm continues to the next window.

#### Time Complexities
| Case | Complexity     | Condition                                   |
|------:|---------------|-----------------------------------------------|
| Average Case   |  O(n + m)   | Occurs when the hash function is "good" (distributed uniformly), resulting in very few spurious hits.   |
| Worst Case | O(n . m) | Occurs when the hash function is "bad" or the prime modulus is too small, causing a collision at almost every window. This forces the algorithm to perform a full string comparison at every step, making it as slow as a naive search. |
